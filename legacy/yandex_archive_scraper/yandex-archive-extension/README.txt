Яндекс Архив — сбор людей округи (расширение для Chrome, версия 1.4.0)
=====================================================================

УСТАНОВКА (один раз)
1. Распакуйте архив в постоянную папку (например, «Документы»). Папку потом не удаляйте и не переносите.
2. В Chrome откройте chrome://extensions
3. Включите «Режим разработчика» (справа вверху).
4. Нажмите «Загрузить распакованное расширение» и выберите папку yandex-archive-extension.
5. Закрепите значок расширения (иконка-пазл в панели Chrome).
При обновлении: замените файлы в папке и нажмите на chrome://extensions круглую стрелку у расширения.
(В версии 1.3.0 файлы parser.js и names.js удалены — старые из папки лучше убрать.)

РАБОТА
1. Войдите в Яндекс в этом же Chrome (откройте https://ya.ru/archive).
2. Нажмите на значок расширения.
3. Раздел 1 — тип обработки: исповедные ведомости или ревизские сказки.
4. Раздел 2 — файл list_links.html со ссылками.
5. Раздел 3 — откуда брать данные на странице (по умолчанию автоопределение; для ревизских сказок не нужен, пока есть данные страницы).
6. «Выбрать, куда сохранить Excel, и начать». Excel обновляется после каждой ссылки.
   Если Яндекс попросит капчу или вход — рабочая вкладка выйдет вперёд: решите и нажмите «Продолжить».

ЧТО НОВОГО В 1.4.0 — «Ревизские сказки» берутся из готовых данных страницы (навык yaarchive-revision-rows)
• Страница Яндекс Архива содержит тег __NEXT_DATA__: все блоки с текстом и точными координатами на скане.
  Для режима «Ревизские сказки» расширение читает именно его (без прокрутки окон и без угадывания геометрии).
  Если тега нет или он от другой страницы, тот же адрес запрашивается с вашей сессией; если и так не вышло —
  работает прежний разбор по окнам страницы (как в 1.3.0).
• Основной блок «Крестьяне» / «Крестьянки» (список людей двора) сохраняется ровно как распознан, БЕЗ деления на людей.
  Рядом по строкам таблицы добавляются: лѣта по ревизии, когда выбыл, в отлучке с, лѣта нынѣ.
  Номер двора берётся из столбца «Семьи» и действует вниз до следующего номера.
• Мужские и женские блоки с одним номером двора попадают в одну строку листа «Люди». Формат ячейки:
      м Никита Григорьевъ Стрѣнинъ ... Петръ
         1) по ревизии: 55. | выбыл: умеръ въ 1847.
         2) по ревизии: 29. | нынѣ: 45.
      ж Степана Никитина жена Марья Иванова Его же дочь Вѣра
         1) нынѣ: 44
  Номер строки идёт сверху вниз, в том же порядке, что и имена в блоке. Число строк равно числу людей в блоке.
• Новый лист «Строки»: та же информация, одна строка Excel = одна строка таблицы (удобно для постобработки).
• Лист «Страницы»: столбец «Проверка итогов страницы». Строки без «Когда выбыл» сверяются с «Итого мужескаго/женскаго пола
  налицо» внизу страницы. Не сошлось — смотрите «Примечание» у двора.
• Имена внутри блока НЕ делятся на людей: в данных нет координат отдельных строк текста.
• Ограничение: страница без шапок «Крестьяне/Крестьянки» (титул, пустой лист) пропускается и помечается в листе «Ссылки».
• При первом запуске дополнительно сохраняется first_page_next_data.json: это тестовый файл для скрипта навыка.
• В архиве есть папка skill/ (SKILL.md и Python-скрипт навыка, тот же алгоритм) и tests/run_fixture.js (самопроверка: node tests/run_fixture.js).
• Режим «Исповедные ведомости» не менялся.

ЧТО НОВОГО В 1.3.0 — принцип: ничего не менять, не достраивать, не удалять
• Разбор имён отменён: нет имени/отчества/фамилии/пола, связей («жена», «сын»...), «С кем связан»,
  статусов, событий, года рождения. Текст записи сохраняется ровно так, как распознан.
• Убраны столбцы: Тип документа, Дата документа (со страницы), Дата в тексте страницы, Страница,
  Строка на странице, Событие, Распознанная строка (и Исходная строка). Во всех трёх листах.
• Сопоставление по расположению блоков на странице (по координатам): № двора ↔ № мужчины / женщины ↔ запись ↔ возраст.
• Одна строка Excel = одна семья-двор. Все люди двора — в ОДНОЙ ячейке, каждый с новой строки:
      м№3 Иван Петров, возр. 45
      ж№1 Мария, возр. 40
  («м»/«ж» — по шапкам «Мужеск. пол» / «Женск. пол» на странице; текст записи — без изменений).
• «Ссылка на страницу» — в строке семьи-двора (страница, где двор начинается).
• Двор может продолжаться на следующей странице — тогда он остаётся одной строкой.

СТОЛБЦЫ ЛИСТА «ЛЮДИ»
Год | Населённый пункт | Двор № | Люди двора | Примечание | Ссылка на страницу
«Примечание» — всё, что стоит проверить глазами: «пол не определён», «несопоставленные числа (стр. N): ...»,
«номер двора не найден», «координаты блоков не получены».

ОТКУДА БЕРУТСЯ БЛОКИ (важно)
Со страницы собираются фрагменты текста с их положением (прямоугольником). Источников два:
  1) окно расшифрованного текста справа от скана; 2) текст, лежащий поверх скана.
Берётся первый источник, который выглядит как таблица (несколько строк и не меньше 3 колонок).
Если ни один не подошёл — запасной режим: записи берутся строками текста как есть, № двора — по маркерам
«Двор № N» / «№ N»; № мужчины/женщины и возраст НЕ сопоставляются (в «Примечании» об этом сказано).
В листе «Ссылки», столбец «Как собрано», видно, какой режим сработал на каждой ссылке.

ОТЛАДКА (нужна для настройки сопоставления под вашу страницу)
При первом запуске в «Загрузки» сохраняются:
  • first_page.html — HTML первой страницы;
  • first_page_debug.json — блоки с координатами обоих источников, адреса запросов страницы и их JSON-ответы.
Пришлите оба файла (и скриншот этой страницы) — по ним сопоставление настраивается точно.

ОГРАНИЧЕНИЯ
• Сопоставление «№ ↔ запись ↔ возраст» определяется геометрически и ещё НЕ проверено на реальных страницах
  Яндекс Архива. Столбцы определяются по шапкам «Двор», «Мужеск. пол», «Женск. пол»; без шапок пол не определяется.
• Если число стоит между двумя записями и неясно, чьё оно, оно относится к ближайшей записи; спорные числа
  попадают в «Примечание».
• Если в списке нет номеров дворов, весь населённый пункт окажется одной строкой (с примечанием).
