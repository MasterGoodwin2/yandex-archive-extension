# Яндекс Архив: строки таблицы вокруг Основного блока

## Что делает

В окне «расшифровка» Яндекс Архива тексты идут вперемешку, а исходный скан это таблица
со столбцами. Навык восстанавливает строки таблицы **без повторного распознавания**:
берёт у страницы готовые блоки (текст + координаты на скане) и для каждого Основного блока
(столбец «Крестьяне» / «Крестьянки», в нём списки людей семьи) присоединяет данные из
соседних столбцов слева и справа по горизонтали строки.

Результат на страницу: блоки -> строки -> ячейки (с id и координатами) + плоский CSV.
В JSON также есть `titles`: тексты шапки страницы (название населённого пункта, дата), по ним
определяется деревня.

Тот же алгоритм перенесён на JS в расширении «Яндекс Архив — сбор людей округи» версии 1.4.0
(`revision-rows.js`, режим «Ревизские сказки»). Python-скрипт и расширение дают одинаковый
результат на странице 165, поэтому правки алгоритма вносите в обе версии.

## Откуда берутся данные

Нужен JSON страницы: `props.pageProps.currentNode`. На странице документа он лежит в теге
`<script id="__NEXT_DATA__" type="application/json">` (по всей видимости, в HTML страницы,
который браузер получает при открытии `.../archive/catalog/<id>/<номер>`). Скрипт принимает:

- файл `.json` с содержимым этого тега, `pageProps` или `currentNode`;
- сохранённый `.html` страницы (тег достанется сам);
- папку с такими файлами (пакетная обработка).

Не проверено: отдаёт ли страница этот тег при обычном запросе без входа в аккаунт.
Проверьте один раз вручную на одной странице (например, `curl -s URL | grep -c __NEXT_DATA__`),
прежде чем строить массовый сбор. При массовой загрузке выдерживайте паузы; у сайта robots.txt
запрещает автоматический доступ и могут быть условия использования, поэтому их стоит
проверить заранее.

## Структура данных (проверено на странице 165, ЦГА Москвы, ф. 51, оп. 8, д. 588)

| Поле | Что внутри |
|---|---|
| `originalImageSize` | ширина и высота скана в пикселях (5609 x 4519) |
| `joinedTextBlocks[i]` | `{id: UUID, points: [4 угла x,y]}`, координаты в пикселях скана |
| `textBlocks[i]` | `{id: "e70b0e3d1669-6f78-...", text: "..."}` |
| `sheetPageNumber`, `id` | номер страницы и id листа |

**Ключевое:** `joinedTextBlocks` и `textBlocks` лежат в **одном порядке**, `i`-й элемент
одного соответствует `i`-му элементу другого. На странице 165 это подтверждено: 72 и 72
элемента, а пара `2769e154-...` -> `e70b0e3d...` (текст «29.») совпала с ответом запроса
`getTextBlockId`, который страница делает при клике по блоку. Идентификаторы двух списков
разного формата, по id связать нельзя, только по индексу.

Поэтому первое правило скрипта: **длины списков не равны -> страница не обрабатывается**,
в отчёт пишется `count_mismatch`. Это единственная защита от тихой ошибки, не обходите её.
Совпадение порядка проверено на одной странице. На новых типах форм сверьте 3-5 страниц
вручную (кликом по блоку в окне № 2 и по `getTextBlockId`).

Разметки построчно (координат отдельных строк текста внутри блока) в данных нет:
`hasStructuredMarkup: false`. Блок «Никита ... Степанъ ... Петръ» это одна строка текста
с одним прямоугольником на всех людей семьи.

## Алгоритм (реализован в `scripts/extract_rows.py`)

1. **Заголовки столбцов по тексту** (нормализация: `ѣ->е`, `і->и`, регистр, знаки):
   «Крестьяне» / «Крестьянки» (Основной, пол M/F), «Семьи», «Лѣта», «Когда именно»,
   «Съ котораго времени». Прямоугольник заголовка задаёт x-границы столбца.
   Это надёжнее гистограммы x: не зависит от наклона и числа блоков.
2. **Половины разворота:** столбцы делятся на левую и правую страницу по `W/2`
   (`--split-x` меняет). Каждый Основной блок получает столбцы только своей половины.
3. **Роли «Лѣта»:** самый левый в группе = `age_prev` (по последней ревизии), самый
   правый = `age_now` (нынче налицо). Если «Лѣта» одно, оно `age_now`.
4. **Всё ниже заголовков** относится к данным. Каждый блок попадает в ближайший столбец по
   центру x (дальше `--col-tol` от любого столбца -> в `orphans`).
5. **Ячейка -> Основной блок** по вертикали: берётся блок, чей диапазон y содержит центр
   ячейки. Если подходит несколько вложенных, берётся **самый низкий** (на странице 165
   блок «Алексѣя Пименова дочери…» охватывает по y блок «Афонасья Пименова жена…»).
   Не содержится ни в одном, но ближе `--near-tol` -> флаг `y_near`.
6. **Номер семьи** (столбец «Семьи») действует вниз, пока не встретится следующий
   (forward-fill): для блока берётся последний номер, чей центр не ниже верха блока плюс
   `--fam-tol`. Флаг `family_changes_inside_block`, если внутри блока встретился ещё номер.
7. **Строки внутри блока:** ячейки сортируются по центру y и склеиваются в строку, если
   перекрываются по y не меньше чем на `--row-overlap` (0.5). Так «55.» и «умеръ въ 1847.»
   попадают в одну строку.
8. **Высокие ячейки** («новорожденные.», высота больше 1.9 медианы) покрывают несколько
   строк: текст ставится в каждую покрытую строку, флаг `span:<столбец>`.
9. **Итоги внизу** («Итого мужескаго/женскаго пола налицо» + число справа) снимаются
   отдельно и **не** попадают в блоки.
10. **Проверка итогов:** число строк без «Когда именно» (т.е. не выбывших) по полу должно
    равняться итогу страницы. На странице 165: М 17 строк - 3 выбывших = 14, Ж 11 = 11.

## Что получается на форме «Ревизская сказка» (страница 165)

Столбцов вокруг Основного блока здесь **меньше, чем 3+3**:

| Половина | Слева | Справа |
|---|---|---|
| Мужская («Крестьяне») | Семьи (`family`) | Лѣта по последней ревизии (`age_prev`), Когда именно выбыл (`departed_when`), Лѣта нынѣ (`age_now`) |
| Женская («Крестьянки») | Семьи (`family`) | Съ котораго времени в отлучке (`absent_since`), Лѣта нынѣ (`age_now`) |

Отдельного столбца «номер человека в переписи» на этой форме нет. Если на других формах он
есть, добавьте его заголовок в `header_kind()` и роль в `CSV_COLS`.

## Запуск

```bash
python scripts/extract_rows.py путь/к/страницам/ --out-json pages.json --out-csv rows.csv
```

Тест: `python scripts/extract_rows.py assets/page165_fixture.json`. Ожидается 7 блоков,
28 строк, `totals_check` с `ok: true` для M (14) и F (11).

Опции допусков (`--fam-tol`, `--near-tol`, `--col-tol`, `--tall`, `--row-overlap`,
`--split-x`) описаны в `--help`. Менять их стоит только после просмотра флагов на
нескольких страницах.

## Выходной формат

CSV (UTF-8 с BOM, одна строка = одна строка таблицы):
`page, node_id, sex, block_no, block_id, family, family_no, row_no, rows_in_block, names_text,
age_prev, age_mid, departed_when, absent_since, age_now, flags`.
`names_text` повторяется в каждой строке блока: для дедупликации группируйте по `block_id`.

JSON: для каждой ячейки есть `text`, `ids` (UUID из `joinedTextBlocks`), `text_block_ids`
и `bbox`, чтобы любую цифру можно было найти на скане и перепроверить.

## Чего навык не делает

- **Не делит текст Основного блока на отдельных людей.** Это задача ваших скриптов
  постобработки. Подсказка: число строк в блоке (`rows_in_block`) совпало с числом людей на
  странице 165 во всех 7 блоках (12, 5, 2, 4, 1, 2, 2). Поэтому строки идут сверху вниз в том
  же порядке, что и имена, и их можно сопоставлять по индексу. Различие чисел это повод
  проверить блок вручную, а не догадываться.
- Не распознаёт сканы, не ходит в сеть, не ведёт сессий.

## Флаги (смотреть до использования данных)

| Флаг | Значение |
|---|---|
| `count_mismatch` (страница) | списки разной длины, страница пропущена |
| `no_main_header` (страница) | не найден заголовок «Крестьяне/Крестьянки», форма другая |
| `totals_mismatch` (страница) | строки не сошлись с итогами внизу |
| `orphans:N` (страница) | N блоков не отнесены ни к столбцу, ни к блоку (список в `orphans`) |
| `family_missing`, `family_changes_inside_block` | номер семьи не найден или сменился внутри блока |
| `nested_block` | ячейка могла подходить нескольким блокам, взят самый низкий |
| `y_near`, `weak_col` | ячейка лежит у границы блока или столбца |
| `span:<столбец>` | значение взято из высокой ячейки |
| `span_conflict:<столбец>`, `multi_cell:<столбец>` | в одном месте несколько значений, проверить |

Отправляйте на ручную проверку страницы с любым флагом уровня страницы и блоки с флагами
`family_*`, `span_conflict`, `multi_cell`. `span:*` и `nested_block` на ожидаемых структурах
(новорожденные, вложенные блоки) обычно допустимы.

## Если форма другая

Другой тип документа (метрические книги, исповедные ведомости) почти наверняка имеет другие
заголовки. Порядок действий: открыть 2-3 страницы, выписать заголовки столбцов и их тексты из
`textBlocks`, добавить их в `header_kind()`, а затем повторить тест с проверкой итогов.
Если у формы нет итогов внизу, проверка 10 недоступна, и надёжность нужно подтверждать
выборочно, по сканам.
