# Запись в GEDCOM

Навык к расширению «Яндекс Архив — сбор людей округи» (2.9.0+; слипшиеся ссылки и `--ranges` — 2.9.1) и независимый скрипт `scripts/gedcom_scans.py`.
Когда на обработку поступает `.ged`, расширение скачивает сканы страниц, на которые он ссылается, и **предлагает записать
ссылки на эти сканы прямо в GEDCOM**. Тот же результат даёт скрипт по готовым `.ged` + `result_links.csv` (побайтово совпадает с расширением).

## Что берётся и куда записывается

| Данные | Откуда | Куда в GEDCOM |
|---|---|---|
| Локальная ссылка на скан (JPG) | столбец «Локальная Ссылка на страницу» (`/Volumes/DATA/Archive_Scans/<файл>.jpg`) | `FILE` (+ `FORM jpg`) |
| Тип документа и год | столбец «Тип документа» («Ревизская сказка от 1850 года») | `TITL` |
| Описание в архиве | столбец «Архив хранения документа» («ЦГА Москвы/Фонд 51/Опись 8/Дело 588/Скан 165») | `PUBL` (источник) или `NOTE` (медиа-объект) |
| Страница в Яндекс Архиве | очищенная ссылка `https://ya.ru/archive/catalog/<дело>/<страница>` | `NOTE`, а в варианте «Источник» ещё `PAGE` у персоны |
| Персона | столбец «ID персоны (INDI)» (@I12@) — по нему запись находит персону; запись `INDI`, где найдена ссылка; для `FAM` — оба супруга; для `SOUR`/`NOTE`/`OBJE` — кто на них ссылается | куда добавляется ссылка |

Ссылка на страницу, у которой скан не скачался или нет персоны (например, ссылка в записи, на которую никто не ссылается),
не записывается — число таких в итоговой строке.

## Два варианта (из трёх выбраны два)

Рассматривались: (1) запись `OBJE` прямо внутри персоны, (2) источник `SOUR` со сканом, (3) общий `OBJE` с указателями.

- **Вариант «Источник» (`source`)** — самый правильный с точки зрения генеалогии: страница документа — это источник, скан — его медиафайл.
  ```
  0 @YA_S1@ SOUR
  1 TITL Ревизская сказка от 1850 года
  1 PUBL Архив хранения документа: ЦГА Москвы/Фонд 51/Опись 8/Дело 588/Скан 165
  1 NOTE Страница в Яндекс Архиве: https://ya.ru/archive/catalog/<дело>/165
  1 OBJE
  2 FILE /Volumes/DATA/Archive_Scans/ЦГА_Москвы_[ЯА]_51-8-588-0165.jpg
  2 FORM jpg
  2 TITL Ревизская сказка от 1850 года, ЦГА_Москвы_[ЯА]_51-8-588-0165.jpg
  ...
  0 @I1@ INDI
  1 SOUR @YA_S1@
  2 PAGE Скан 165, https://ya.ru/archive/catalog/<дело>/165
  ```
  Плюс: программы показывают «Источники» персоны с подтверждением и сканом. Подходит для MyHeritage, Gramps, RootsMagic и т. п.
- **Вариант «Общий медиа-объект» (`media`)** — файл объявляется один раз, персоны на него ссылаются; страница на нескольких людей = один объект.
  ```
  0 @YA_M1@ OBJE
  1 FILE /Volumes/DATA/Archive_Scans/ЦГА_Москвы_[ЯА]_51-8-588-0165.jpg
  1 FORM jpg
  1 TITL Ревизская сказка от 1850 года
  1 NOTE Архив хранения документа: ЦГА Москвы/Фонд 51/Опись 8/Дело 588/Скан 165
  2 CONT Страница в Яндекс Архиве: https://ya.ru/archive/catalog/<дело>/165
  ...
  0 @I1@ INDI
  1 OBJE @YA_M1@
  ```
  Плюс: проще и компактнее; фото видно у персоны без источника.

Вариант (1) не выбран: он дублирует файл и описание для каждого человека на одной странице и не фиксирует источник.
Расположение `FILE`/`FORM` — как в GEDCOM 5.5 (на одном уровне); большинство программ читают и 5.5.1.

## Расширение

В окне — раздел «Запись сканов в GEDCOM» (виден, когда выбран `.ged`): флажок включения, вариант (по умолчанию «Источник») и место записи:
в копию `<имя>_со_сканами.ged` в папке результата (по умолчанию, исходный не меняется) или в исходный файл (рядом сохраняется
`<имя>_до_сканов.ged`; Chrome попросит разрешение на запись). Запись идёт после скачивания всех сканов; итог — в журнале.

## Скрипт

```
python scripts/gedcom_scans.py проект.ged result_links.csv --variant source [--out итог.ged] [--in-place]
```

Таблица — `result_links.csv` расширения (UTF-8, «;»; прежний `.xlsx` тоже читается, для него нужен `openpyxl`). Она должна быть сделана по этому же `.ged`:
страницы сопоставляются по столбцу «Очищенная ссылка» (в таблицах до 2.9.2 — по порядку строк; при расхождении числа страниц скрипт останавливается).
Параметр `--ranges` нужен, если при скачивании была отмечена «Разворачивать диапазон…».

## Если у персоны уже есть такая запись

Существующие записи файла не дублируются и не правятся. Для каждой пары «персона — страница» проверяется, есть ли уже:
- **источник** — `SOUR`, на который ссылается персона (в `INDI`, в том числе в цитате), со ссылкой ya.ru на эту страницу или файлом этого скана;
- **медиа-объект** — `OBJE` персоны (внутри или указателем) с `FILE` этого скана или ссылкой на эту страницу.

Выбранный пользователем вариант пишется, только если такой записи у персоны ещё нет. Если выбранный вид уже есть — запись идёт **другим вариантом**
(выбран «Источник», а источник уже есть → «Общий медиа-объект»; и наоборот). Есть оба вида — для этой персоны страница пропускается.
Итог: «другим вариантом N, пропущено M». Слипшиеся ссылки («…/7; …/278» без пробелов) делятся на отдельные, каждая — своей персоне.

## Правила записи

- Свои записи помечены `@YA_S1@…` / `@YA_M1@…`; при повторном запуске (или смене варианта) прежние записи и ссылки на них сначала убираются — дублей нет.
- Остальные строки файла не меняются; окончания строк сохраняются; длинные значения режутся на `CONC` по 200 символов, переводы строк — `CONT`.
- Файл пишется в UTF-8, в шапке `1 CHAR UTF-8` (исходная кодировка — UTF-8/UTF-16/Windows-1251 — читается автоматически).
- Исходный файл без запасной копии не перезаписывается: режим «в исходный файл» сначала сохраняет `_до_сканов.ged`.

## Встроено в расширение (с версии 3.0.0)

Этот навык входит в расширение Chrome «Яндекс Архив — сбор людей округи» и работает внутри него — запускать скрипты в Терминале не требуется. Скрипты в `scripts/` оставлены как справочная копия логики и для проверок.
