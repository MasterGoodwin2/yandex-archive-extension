# yaarchive — общий скрипт обработки Яндекс Архива

**3.2.2:** в комплекте расширение 2.9.3 («Запись в GEDCOM» не дублирует имеющиеся записи персоны).

**3.2.1:** в комплекте расширение 2.9.2 (результат образов страниц — UTF-8 CSV).

**3.2.0:** столбец «Архив хранения документа» (прежнее «Ссылка на ЦГА Москвы»); сканы ищутся и в `/Volumes/DATA/Archive_Scans` (папка по умолчанию расширения 2.7.0+), помимо «Archive_Scans» рядом с результатом и `--scans`.

Один файл `yaarchive.pyz` объединяет всё, что раньше было разнесено по навыкам и скриптам:

| Было | Что делает | В общем скрипте |
|---|---|---|
| `extract_confession.py` + `split_names.py` | исповедные ведомости: столбцы, номера, люди | этап 5 |
| `extract_rows.py` + `revision_people.py` | ревизские сказки: строки, люди, родство, выбытие | этап 5 |
| навык «Сохранить Скан» (`link_scans.py`) | имя скана по делу, ссылка на скан | этап 12 |
| `rebuild_from_debug.js` | пересчёт из отладочного пакета | заменён: скрипт всегда считает из пакетов |
| `names_ru.json`, порядок НП, слова родства, годы ревизий | справочники | `справочники.json` (один файл) |
| — (новое) | родство и отчество в исповедных ведомостях, Excel + GEDCOM, слежение за папкой | этапы 9, 15 |
| — (новое) | **навык «Исправление ошибок»** с вашим подтверждением | этапы 14, 16 |

Загрузку страниц и сканов по-прежнему делает **расширение Chrome** (нужен вход в Яндекс). Расширение **2.2.0** всегда
сохраняет данные каждой страницы и `run_summary.json` (раньше — только исповедные и только с галочкой отладки).

## Установка (macOS, один раз)

1. Обновите расширение до 2.9.3 (папка `yandex-archive-extension`, на chrome://extensions — «Обновить»).
2. Положите `yaarchive.pyz` и `yaarchive_запуск.command` **в папку со списком ссылок** (там, где `list_links.html`
   и куда расширение пишет `yaarchive_debug/`).
3. Первый запуск: правый щелчок по `yaarchive_запуск.command` → «Открыть» (macOS спросит подтверждение один раз).
   Нужен Python 3 (на Mac обычно есть; если нет — https://www.python.org/downloads/). Библиотека openpyxl
   ставится сама при первом запуске.

Windows: `yaarchive_запуск.bat` (нужен Python с python.org).

## Работа

Двойной щелчок по `yaarchive_запуск.command` — откроется окно, скрипт **следит за папкой**:

* расширение закончило загрузку → через 20 с пакет обработан, итог обновлён — сам;
* вы рядом с окном → скрипт сразу спрашивает про исправления (д / н / дв — да всем такого вида / нв / п — позже / ?);
* вас нет → предложения ждут в листе **«Исправления»** файла `Итог/Итог_люди.xlsx`: впишите «да» или «нет»,
  сохраните файл — скрипт сам применит и пересчитает;
* вы поправили значение прямо в листе «Люди» (имя, возраст, двор, НП, пол, номер, отчество, ID отца…) и сохранили —
  скрипт заметит правку и попросит подтвердить; подтверждённая сохраняется навсегда (`Итог/исправления.json`).

Разовый запуск без слежения: `python3 yaarchive.pyz ПАПКА --once`. Все параметры: `python3 yaarchive.pyz --help`.

## Порядок обработки (почему именно такой)

| № | Этап | Почему здесь |
|---|---|---|
| 1 | Пакеты: готов, когда есть `run_summary.json` и файлы не меняются 20 с | не читать пакет, который ещё пишется |
| 2 | Страницы: проверка целостности; страница из нескольких пакетов — из самого нового | повторная загрузка заменяет старую, без дублей |
| 3 | Документы: год + дело, **сортировка по номеру страницы числом** | раньше файлы шли по имени: `p100` раньше `p99`, а разные годы смешивались в один документ |
| 4 | Тип документа по тексту страниц (большинство), иначе — тип запуска | ошибочно выбранный в расширении тип не портит результат |
| 5 | Разбор (навыки исповедных ведомостей и ревизских сказок) | переносы НП/двора/семьи работают только внутри документа и по порядку |
| 6 | НП к одному виду по справочнику; «не определён» → следующий определённый НП | «д. Черепкова» = «деревня Черепкова» |
| 7 | **Принятые исправления значений**: НП, двор, пол, номер, возраст, текст; затем повторный НП — к первичному | до родства и года рождения — чтобы исправление разошлось по всем зависимым данным |
| 8 | Пустой «Двор №» по соседним дворам | после исправлений двора |
| 9 | Родство: глава, жена, дети, братья; отчество детей от имени отца; отец по отчеству | после исправлений текста/пола/возраста |
| 10 | **Принятые исправления родства** и года рождения | поверх вычисленного |
| 11 | Год рождения = год документа − возраст | после исправлений возраста |
| 12 | Сканы: имя файла по делу, поиск в `Archive_Scans` | |
| 13 | Проверка: что посмотреть глазами | |
| 14 | **Навык «Исправление ошибок»**: предложения | по уже исправленным данным — без повторов |
| 15 | Итог: Excel, GEDCOM, JSON, отчёт | |
| 16 | Диалог / лист «Исправления» → принятые применяются, итог пересчитывается | |

## Навык «Исправление ошибок»

Ничего не меняет без вашего «да». Находит и предлагает:

| Вид | Пример |
|---|---|
| Номер человека | сквозные номера женщин 8, **6**, 10 → 9 |
| Номер двора | дворы 4, **7**, 6 → 5 (сразу для всех людей двора) |
| Имя и пол | тексты двух соседей перепутаны (женское имя у мужского номера и наоборот) |
| Имя не найдено | в тексте семьи осталось одно имя подходящего пола |
| Сдвиг возрастов | пропущенная цифра сдвинула возрасты: «сын» старше отца → сдвиг на строку |
| Родство | «сын» почти ровесник отца, сдвиг не помогает → снять связь |
| Возраст | 125 → 25 (лишняя цифра) |
| Возраст по ревизиям | 1834: 10 лет, 1850: 40 лет — не сходится |
| Дозагрузка страниц | не загрузились / пропущены → файл `Дозагрузка_страниц.html` для расширения |
| Ваша правка в Excel | любое значение, изменённое вами в листе «Люди» |

Решения хранятся в `Итог/исправления.json`, применяются при каждом пересчёте (новые пакеты, новая версия
алгоритма). Снять решение — «отменить» в истории листа «Исправления».

## Итог (папка `Итог/`)

* `Итог_люди.xlsx` — листы «Люди», «Исправления», «Семьи», «Страницы», «Проверка», «Сводка», «Об обработке».
  Лист «Люди» (3.1.0, как в расширении 2.3.0): у всех людей одной страницы одна слитая ячейка «Год», «Ссылка на страницу»,
  «Локальная Ссылка на страницу», «Архив хранения документа» (текст «ЦГА Москвы/Фонд…/Скан N», без ссылки); «Номер» перед
  «Человек»; НП «не определён» → следующий определённый; повторный НП документа перенесён к первичному. Цвета (светлые,
  кроме красного): НП — закреплены за названием (справочник «цвета»), дворы и блоки страниц — чередуются, мужчины —
  голубые, женщины — розовые, ошибки — светло-красные, двор курсивом — вычислен;
* `Итог_древо.ged` — GEDCOM 5.5.1 для MyHeritage: персоны, семьи (муж–жена–дети), год рождения ≈, источник
  (архив, фонд, опись, дело, скан), текст записи. **Каждая запись документа — отдельная персона**: один и тот же человек
  в 1739 и 1750 гг. не объединён — импортируйте в отдельное дерево для поиска совпадений;
* `Итог_люди.json` — то же для своих программ; `Отчёт.txt`; `yaarchive_журнал.txt`.

Итог накопительный: все пакеты папки, повторно загруженные страницы — из самого нового пакета.

## Справочники

`справочники.json`: имена (М/Ж), слова родства и их нормальные формы, местоимения, приметы («увечен» — не фамилия),
населённые пункты (шаблоны, порядок до/с 1750 г., синонимы), исключения отчеств (Павел → Павлов, Михаил → Михайлов),
годы ревизий, пороги проверок. Свою копию положите рядом с `yaarchive.pyz` — она заменит встроенную.

## Для разработки

```
python3 yaarchive/yaarchive.py ПАПКА --once        # из репозитория, без сборки
python3 yaarchive/tests/test_yaarchive.py          # проверка общего скрипта
python3 yaarchive/build.py                          # сборка dist/yaarchive.pyz и файлов запуска
```
Требуется Python 3.9+ (проверено на 3.9 и 3.13) и openpyxl.
