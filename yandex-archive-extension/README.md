Яндекс Архив — сбор людей округи (расширение для Chrome, версия 3.0.1)
=====================================================================

УСТАНОВКА (один раз)
1. Распакуйте архив в постоянную папку (например, «Документы»). Папку потом не удаляйте и не переносите.
2. В Chrome откройте chrome://extensions
3. Включите «Режим разработчика» (справа вверху).
4. Нажмите «Загрузить распакованное расширение» и выберите папку yandex-archive-extension.
5. Закрепите значок расширения (иконка-пазл в панели Chrome).
При обновлении: замените файлы в папке и нажмите на chrome://extensions круглую стрелку у расширения.
(В версии 1.3.0 файлы parser.js и names.js удалены — старые из папки лучше убрать.)

РАБОТА
1. Войдите в Яндекс в этом же Chrome (откройте https://ya.ru/archive).
2. Нажмите на значок расширения.
3. Раздел 1 — тип обработки: исповедные ведомости или ревизские сказки.
4. Раздел 2 — «Выбрать папку, где лежит файл ссылок» (list_links.html; если HTML-файлов несколько — выберите в списке).
   Папка запоминается; при следующем запуске Chrome один раз попросит подтвердить доступ.
5. Раздел 3 — откуда брать данные на странице (по умолчанию автоопределение; для ревизских сказок не нужен, пока есть данные страницы).
6. «Начать». Всё сохраняется автоматически в «<папка ссылок>/yaarchive_debug/<дата_время запуска>/»:
   result.xlsx (обновляется после каждой ссылки), run_log.txt, run_summary.json, файлы по каждой странице.
   Если Яндекс попросит капчу или вход — рабочая вкладка выйдет вперёд: решите и нажмите «Продолжить».

ЧТО НОВОГО В 3.0.1 — «Скачать графические образы страниц»: диапазоны не раскрываются
  Из каждой ссылки берётся только указанная в ней страница; диапазоны («от…до») не вычисляются и не обрабатываются, переключатель «Разворачивать диапазон» удалён.

ЧТО НОВОГО В 3.0.0 — всё в одном расширении, Терминал не нужен
  Общий скрипт yaarchive (итоговая таблица людей, родство, дворы, годы рождения, GEDCOM, навык «Исправление ошибок») и навык «Строки таблицы»
  встроены в расширение и работают внутри Chrome (Python в WebAssembly, движок — папка engine/). Установка Python, pip и запуск в Терминале не нужны.
  • Раздел «Итоговая обработка»: после запуска (флажок включён по умолчанию) или кнопкой «Выполнить итоговую обработку папки результата сейчас» —
    в папке результата создаётся «Итог/»: Итог_люди.xlsx, Итог_древо.ged, Итог_люди.json, Отчёт.txt.
  • Сканы из «Archive_Scans» подключаются к итогу по именам файлов; путь в ссылке — как в поле «Локальный путь» (по умолчанию /Volumes/DATA/Archive_Scans).
  • Предложения исправлений показываются в окне раздела: «да — исправить», «нет — больше не предлагать», «Применить решения» — итог пересчитывается.
    Решения «Исправления» в листе Excel и ручные правки в листе «Люди» тоже учитываются при следующей итоговой обработке.
  • Навыки «Сохранить Скан», «Запись в GEDCOM» и «Строки таблицы» входят в расширение; отдельные .skill-файлы и скрипты в Терминале больше не обязательны.
  Первый запуск итоговой обработки загружает движок (около 10 секунд), дальше быстрее.

ЧТО НОВОГО В 2.9.3 — «Запись в GEDCOM» не дублирует уже имеющиеся записи
  Если у персоны в .ged уже есть запись об этой странице, она не дублируется и не меняется; новая запись пишется ДРУГИМ вариантом, не выбранным пользователем:
  • «уже есть источник» — источник SOUR, на который ссылается персона, содержит ссылку ya.ru на эту страницу или файл этого скана (OBJE/FILE);
  • «уже есть медиа-объект» — OBJE персоны (внутри или указателем), у которого FILE — этот скан или ссылка на эту страницу.
  Выбран «Источник» и такой источник уже есть → пишется «Общий медиа-объект» (и наоборот). Есть оба вида — страница для этой персоны пропускается.
  Итог в журнале: «другим вариантом записано N, пропущено M». Слипшиеся ссылки делятся на отдельные (с 2.9.1), каждая — своей персоне.

ЧТО НОВОГО В 2.9.2 — результат типа «Скачать графические образы страниц» — UTF-8 CSV, а не Excel
  • Вместо result_links.xlsx — result_links.csv (основная таблица) и result_links_all.csv (все найденные ссылки): UTF-8 с BOM,
    разделитель «;», поля в кавычках по RFC 4180. Кодировки Excel больше не мешают; при желании файл открывается и в Excel.
  • Для GEDCOM первыми столбцами идут «ID персоны (INDI)» (номер записи, например @I12@; для ссылки в семье FAM — оба супруга через «; ») и
    «Имя персоны» (для чтения: имена повторяются, ID — нет). По ID навык «Запись в GEDCOM» находит персону в файле.
  • Новые столбцы: «Очищенная ссылка» (https://ya.ru/archive/catalog/<дело>/<страница> — ключ страницы) и «Статус скана»
    («сохранён» / «не скачан: причина»); «Локальная Ссылка на страницу» содержит только путь, без текста ошибки.
  • Навык «Запись в GEDCOM» (gedcom_scans.py) читает result_links.csv и сопоставляет страницы по «Очищенная ссылка».
  • Основной result.xlsx для исповедных ведомостей и ревизских сказок не менялся.

ЧТО НОВОГО В 2.9.1 — слипшиеся ссылки и диапазоны
  Слипшиеся ссылки в GEDCOM/HTML («…/7; …/278; …/242;» и без пробелов: «…/7;https://…/278») теперь делятся на отдельные;
  каждая записывается той персоне, из чьих данных взята (раньше такие ссылки пропускались целиком).
  Диапазон страниц из ссылок поиска (sheet_page_from…sheet_page_to) по умолчанию НЕ разворачивается: скачивается страница, на которую
  указывает ссылка, а в «Все ссылки» пишется пометка. Включается отметкой «Разворачивать диапазон…» (в скрипте навыка — --ranges).
  Обычные ссылки …/catalog/<дело>/<страница> всегда дают ровно одну страницу.

ЧТО НОВОГО В 2.9.0 — навык «Запись в GEDCOM»
  Если на обработку поступил .ged, в окне появляется раздел «Запись сканов в GEDCOM». После скачивания сканов расширение вносит в GEDCOM
  у каждой персоны ссылку на локальный скан (JPG), название документа с годом («Тип документа») и архив хранения.
  Два варианта: «Источник» (запись SOUR со сканом OBJE и у персоны ссылка SOUR/PAGE) и «Общий медиа-объект» (запись OBJE, у персоны ссылка на неё).
  Куда: в копию <имя>_со_сканами.ged (по умолчанию) или в исходный файл (рядом остаётся <имя>_до_сканов.ged).
  Повторный запуск не даёт дублей. Тот же результат — скрипт skill/zapis-v-gedcom/scripts/gedcom_scans.py.

ЧТО НОВОГО В 2.5.0 — «Скачать графические образы страниц из списка ссылок»
Отдельный режим: данные людей не разбираются, сохраняются только сканы страниц (навык «Сохранить Скан», Scrpt_YA_Orig_Scan).
• Источник — HTML-файл со списком ссылок или GEDCOM существующего генеалогического проекта (.ged; UTF-8, UTF-16 или windows-1251):
  из него собираются все ссылки с доменами ya.ru и yandex.ru (в том числе разорванные на строки CONC/CONT).
• Ссылки приводятся к виду https://ya.ru/archive/catalog/<дело>/<страница>: параметры «?center=…», «zoom» и т. п. отбрасываются,
  yandex.ru приравнивается к ya.ru. Дубликаты удаляются. Ссылка-диапазон (поиск, sheet_page_from…to) раскрывается в отдельные страницы.
  Ссылки без номера страницы (дело или опись целиком) и не относящиеся к Яндекс Архиву пропускаются и отмечаются в Excel.
• В выбранную папку записываются (с 2.9.2 — CSV вместо Excel): result_links.csv — столбцы «Исходная ссылка», «Локальная Ссылка на страницу»
  (ссылка на файл скана в Archive_Scans/), «Архив хранения документа» (текст «ЦГА Москвы/Фонд…/Опись…/Дело…/Скан…»), result_links_all.csv
  (каждая найденная ссылка: ссылка для скачивания, статус — страница / диапазон / дубликат / пропущена, место в GEDCOM: INDI/SOUR, имя, тег);
  list_links_fixed.html — исправленный список без повторов; папка Archive_Scans; links_run_log.txt.
• Уже скачанные сканы пропускаются (страница даже не открывается). Страницы, не отдавшие данные, повторяются: три попытки сразу
  и ещё один проход в конце.
• В основном режиме: страница, которая не загрузилась, теперь повторяется автоматически, попадает в журнал сразу
  («ВНИМАНИЕ: страница … не загружена») и в итоговый список «не загружено страниц».
• Результат в Excel остаётся отдельным от основного result.xlsx, поэтому файлы не перезаписывают друг друга.

ЧТО НОВОГО В 2.4.0 — точнее разбор исповедных ведомостей (по отладочному пакету 2.3.0: 45 ссылок, 996 страниц)

  положению (с учётом наклона скана), проверка — номера в каждой части идут подряд. Было «возраст без номера» 5071,
  стало 2733; «нет номера» 5150 → 3739; «нет возраста» 4751 → 3356.
• Возраст строкой ниже номера (частая запись) — привязывается к своему человеку (ⓘ в «Примечании»).
• Формы без нумерации людей (1795 и др.): отсутствие номера больше не считается ошибкой (ⓘ на странице).
• Имена: старые написания (Микита, Осиф, Орина, Офросиня, Улияна, Огафия…) и «де» перед именем
  («дети их Михаила») — «без имени» 7059 → 5585.
• Населённые пункты: длинный заголовок «Деревни Мякининой Генералъ-Лейтенанта Бутурлина…» больше не теряется
  (Мякинина — 481 чел.); новая деревня Екатериненская (1829–1845, 341 чел.); заголовок, слитый с первой семьёй,
  — и заголовок, и семья; итоговые фразы ведомости («Сверхъ вышеписаннаго…») — не семья.
• Год: если в файле ссылок у ссылки нет года — берётся из названия дела («6 ревизия» → 1811).
• Ревизская сказка, запущенная в режиме «Исповедные ведомости» (и наоборот), — предупреждение ⚠ в «Примечании» и
  на листе «Ссылки».
• Новые пояснения по-русски; пояснения (ⓘ) не красятся как ошибки.

ОТКУДА БЕРУТСЯ БЛОКИ (важно)
Со страницы собираются фрагменты текста с их положением (прямоугольником). Источников два:
  1) окно расшифрованного текста справа от скана; 2) текст, лежащий поверх скана.
Берётся первый источник, который выглядит как таблица (несколько строк и не меньше 3 колонок).
Если ни один не подошёл — запасной режим: записи берутся строками текста как есть, № двора — по маркерам

В листе «Ссылки», столбец «Как собрано», видно, какой режим сработал на каждой ссылке.
